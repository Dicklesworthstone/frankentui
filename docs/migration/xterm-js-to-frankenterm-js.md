# Migrating from xterm.js to FrankenTermJS

> The top-level migration guide for replacing **xterm.js** with **FrankenTermJS**
> as your web terminal engine. It maps the everyday xterm.js surface to its
> FrankenTermJS equivalent, calls out **intentional divergences**, and ties each
> behaviour back to the release-blocking compatibility harnesses.
>
> Companion guides:
> - Base terminal contract & versioning: [`docs/spec/frankenterm-web-api.md`](../spec/frankenterm-web-api.md) (canonical)
> - Advanced host API (events, parser hooks, markers, runtime options): [`advanced-host-api.md`](./advanced-host-api.md)
> - Pane workspaces (no xterm.js equivalent): [`flex-to-pane-and-versioning.md`](./flex-to-pane-and-versioning.md)

## What FrankenTermJS is (and is not)

FrankenTermJS is **not a fork or a port of xterm.js**. The terminal engine
(parser, grid, scrollback, selection, reply engine, shaping) lives in Rust/WASM;
the browser layer is a thin host shim. Three consequences shape every mapping
below:

1. **Rust-first.** The behaviour you depend on is defined by the Rust core and
   the stable contract in [`frankenterm-web-api.md`](../spec/frankenterm-web-api.md),
   not by JS internals.
2. **Deterministic.** Identical inputs + time + capability profile produce
   identical output. Every source of nondeterminism is explicit and logged.
3. **Bounded.** No unbounded buffers or queues; remote mode has explicit flow
   control.

### Where the code lives (transience caveat)

The browser-facing `frankenterm-web` WASM package is a *transient/extracted*
crate (repeatedly split out and folded back in), so treat it as the JS-binding
wrapper, not the source of truth. The durable, in-tree homes are the `ftui-*`
crates:

## Mental-model shift (read this first)

xterm.js is **callback-driven and mutable**: you register `onData`/`onKey`
handlers and the terminal pushes to them. FrankenTermJS is **drain-driven and
deterministic**: the host advances time/inputs and **drains** ordered queues each
render tick. This is the single biggest porting change.

| xterm.js idiom | FrankenTermJS idiom |
|----------------|---------------------|
| `term.onData(cb)` | call `input(...)` then `drainEncodedInputs()` / `drainEncodedInputBytes()` per tick |
| `term.onKey(cb)` | same drain model; key encoding is deterministic |
| `term.onRender(cb)` | host owns the render loop; call `render()` and apply patches |
| event listeners | `createEventSubscription(types)` → `drainEventSubscription()` (FIFO by monotonic `seq`) |
| global addon registry | first-party methods behind stable names + capability flags |

Drain at least once per render tick; every drainable queue is bounded
(drop-oldest) — see the **Bounded Buffering Contract** in the spec.

## Lifecycle & rendering

| xterm.js | FrankenTermJS | Notes |
|----------|---------------|-------|
| `new Terminal(opts)` | construct + `init(...)` | options validated atomically (see runtime options) |
| `term.open(el)` | `init(...)` + host attaches the canvas/DOM | host owns the element |
| `term.resize(c, r)` | `resize(cols, rows)` | deterministic reflow |
| `FitAddon.fit()` | `fitToContainer(...)` | first-party; see addon table |
| devicePixelRatio handling | `setScale(...)` / `setZoom(...)` | DPR/zoom are explicit, not implicit |
| renderer choice (`dom`/`canvas`/`webgl`) | `rendererBackend(...)` | default `Dom`; WebGPU-first with fallback |
| `term.refresh()` / internal | `render()` | host drives the frame |
| `term.dispose()` | `destroy()` | RAII teardown |

## Writing & feeding data

| xterm.js | FrankenTermJS | Notes |
|----------|---------------|-------|
| `term.write(data)` / `writeln` | `feed(bytes)` | feeds VT/ANSI bytes into the parser |
| terminal replies (DA/DSR…) | `drainReplyBytes()` | FIFO reply chunks generated by `feed()` |
| `term.write(cb)` flush callback | deterministic: replies are queued, not callback'd | drain after `feed()` |

## Input & the typed event model

| xterm.js | FrankenTermJS | Notes |
|----------|---------------|-------|
| `onData` / `onKey` | `input(json)` → `drainEncodedInputs()` / `drainEncodedInputBytes()` | FIFO across `input()` calls |
| `attachCustomKeyEventHandler` | host filters before `input(...)`; key binding is host-layer | see advanced-host-api `§1` |
| IME composition | `imeState()` + `drainImeCompositionJsonl()` | composition rewrites emitted before primary event |
| custom event bus | `createEventSubscription(types)` → `drainEventSubscription[Jsonl]()` → `closeEventSubscription()` | per-subscription FIFO by global `seq` |

The host-observable **event taxonomy** and the **typed error model** are defined
once in `crates/ftui-web/src/sdk_event_model.rs` and shipped as TypeScript in
`crates/ftui-web/sdk/frankenterm-js-events.d.ts` (kept in lockstep by
`bd-2vr05.9.2`'s harness). Import `HostEventClass` / `SdkErrorCode` instead of
hard-coding strings:

```ts
import type { HostEvent, HostEventClass, SdkError } from "frankenterm-js-events";

// e.g. "input.key" | "input.paste" | "terminal.progress" | "ui.link_click" | ...
sub = term.createEventSubscription(["input.key", "ui.link_click"]);
for (const ev of term.drainEventSubscription(sub) as HostEvent[]) {
  if (ev.type === "ui.link_click") openTrusted(ev.payload);
}
```

## Remote attach (no xterm.js equivalent)

xterm.js has no built-in transport; you wire your own WebSocket. FrankenTermJS
ships a deterministic attach **state machine** with bounded flow control:

`attachConnect` → `attachTransportOpened` → `attachHandshakeAck` →
(`attachTick` / `attachTransportClosed` / `attachProtocolError` /
`attachSessionEnded`) → `attachClose` / `attachReset`, with
`drainAttachTransitionsJsonl()` preserving transition order. See the
[websocket protocol spec](../spec/frankenterm-websocket-protocol.md) and the
flow-control bounds enforced by the security/reliability gate (`bd-2vr05.11.6`).

## Viewport, scrollback & search

| xterm.js | FrankenTermJS |
|----------|---------------|
| `term.scrollLines/Pages` | `scrollLines(...)` / `scrollPages(...)` |
| `term.scrollToTop/Bottom` | `scrollToTop()` / `scrollToBottom()` / `scrollToLine(...)` |
| `term.buffer` introspection | `viewportState()` / `viewportLines()` / `snapshotScrollbackFrameJsonl()` |
| `SearchAddon.findNext/Previous` | `searchNext()` / `searchPrev()` (+ `setSearchQuery`, `searchState`, `clearSearch`) |

## Selection, clipboard & links

| xterm.js | FrankenTermJS | Divergence |
|----------|---------------|------------|
| `term.select(...)` / `getSelection()` | `setSelectionRange(...)` / `extractSelectionText()` | — |
| clipboard write | `copySelection()` + `clipboardPolicy()` / `setClipboardPolicy()` | **host-managed**: `copySelection()` returns text but does not write the system clipboard directly; use a trusted user gesture |
| paste | `pasteText(...)` | **bounded**: payloads over `maxPasteBytes` (default `786432`) are rejected (`clipboard.paste_too_large`) |
| `WebLinksAddon` | `linkAt` / `linkUrlAt` / `drainLinkClicks[Jsonl]` / `setLinkOpenPolicy` / `linkOpenPolicy` / `setHoveredLinkId` | **HTTPS-only by default** (`allowHttp=false`); control bytes in URLs are sanitized to nothing |

## Accessibility & shaping

| xterm.js | FrankenTermJS |
|----------|---------------|
| `screenReaderMode` option | `setAccessibility(...)` / `accessibilityState()` |
| accessibility tree / DOM mirror | `accessibilityDomSnapshot()` / `accessibilityClassNames()` / `screenReaderMirrorText()` + `drainAccessibilityAnnouncements()` |
| cursor style options | `setCursor(...)` |
| `disableLigatures` / ligature addon | `setTextShaping(...)` / `textShapingState()` (policy `auto`/`enabled`/`disabled`, deterministic grapheme fallback) |

## Addon-class replacements

xterm.js addons become first-party methods behind stable names + capability
flags. The in-tree behaviour is validated by the **addon-parity** harness
(`scripts/frankenterm_js_addon_parity_compat.sh`, `bd-2vr05.14.6`).

| xterm.js addon | FrankenTermJS replacement | In-tree home | Notes / divergence |
|----------------|---------------------------|--------------|--------------------|
| `xterm-addon-fit` | `fitToContainer(...)` | `ftui-render/src/fit_metrics.rs` | sub-pixel scaling is **not** linear; a tiny container clamps to `1×1` (never errors) |
| `xterm-addon-web-links` | `linkAt`/`linkUrlAt`/`drainLinkClicks`/`setLinkOpenPolicy` | `ftui-render/src/ansi.rs` (OSC-8) | HTTPS-only default; control-byte/oversize URLs sanitized |
| `xterm-addon-image` | inline-image protocol detection (`ImageProtocol`) | `ftui-extras/src/image.rs` (`image` feature) | deterministic priority ladder `kitty > iterm2 > sixel > ascii` |
| progress (`OSC 9;4`) | `terminal.progress` event | out-of-tree (`frankenterm-web`); see spec `§ Progress Signal Mapping` | malformed payloads emit deterministic rejection envelopes |
| ligatures | `setTextShaping` / `textShapingState` | `ftui-text/src/shaping_fallback.rs` | requested-but-unsupported ligatures fall back to canonical grapheme boundaries (no backend variability) |
| web fonts / metric changes | font/DPR/zoom transitions invalidate shaped-run cache | `ftui-render/src/fit_metrics.rs` + shaping | cache keys include OpenType feature state + font identity/size so toggles cannot alias |

## Typed errors

Replace xterm.js's ad-hoc throws with the stable `SdkErrorCode` set (see
`frankenterm-js-events.d.ts`): `attach.protocol_error`,
`capability.unsupported`, `clipboard.disabled`, `clipboard.paste_too_large`,
`input.parse`, `queue.overflow`, `terminal.progress.malformed`,
`ui.link.blocked`. These are stable for the `1.x` line and map to the contract's
documented rejection/policy surfaces.

## Intentional divergences (and how to configure equivalent behaviour)

- **Drain model, not callbacks.** Pull ordered queues each tick instead of
  registering listeners. To approximate `onData`, drain `drainEncodedInputs()`
  in your render loop.
- **Host-managed clipboard.** `copySelection()` returns text; the host performs
  the privileged clipboard write under a user gesture. Tighten/disable via
  `setClipboardPolicy(...)`.
- **HTTPS-only links by default.** Opt into HTTP per host via
  `setLinkOpenPolicy({ allowHttp: true, allowedHosts: [...] })` — only if you
  must.
- **Bounded everything.** Queues are drop-oldest with documented maxima; a drop
  surfaces as `queue.overflow`. Size `event_subscription` queues up to `8192`.
- **Deterministic time.** The host advances the clock; there is no implicit
  wall-clock animation timing.

## Framework wiring

**Vanilla** (drain loop):

```ts
const term = await FrankenTermWeb.init({ cols: 80, rows: 24 });
function tick() {
  for (const patch of term.render()) applyPatch(patch);
  for (const reply of term.drainReplyBytes()) socket.send(reply);
  requestAnimationFrame(tick);
}
socket.onmessage = (e) => term.feed(new Uint8Array(e.data));
container.addEventListener("keydown", (e) => term.input(encodeKey(e)));
requestAnimationFrame(tick);
```

**React/Next** (lifecycle in an effect): construct in `useEffect`, drive the
drain loop with `requestAnimationFrame`, and `destroy()` in the cleanup. First-
party adapter packages are tracked by `bd-2vr05.9.3` and live alongside the
out-of-tree `frankenterm-web` package.

## Capability probing & versioning

Pin to `apiLine + major(apiVersion)` and probe capabilities via `apiContract()`
rather than duck-typing methods:

```ts
const c = term.apiContract();          // { apiLine, apiVersion, eventTypes, methods, ... }
if (c.apiLine !== "frankenterm-js" || major(c.apiVersion) !== 1) bailOut();
```

`minor` upgrades are additive/safe; `major` requires consulting this guide.

## Troubleshooting via structured logs

Every behaviour above is validated by a release-blocking harness that emits a
JSONL manifest you can grep:

| Symptom | Harness / log |
|---------|---------------|
| event taxonomy / typed errors / `.d.ts` drift | `scripts/frankenterm_js_sdk_contract_compat.sh` → `sdk_contract_compat_manifest.jsonl` |
| fit / links / image / ligature parity | `scripts/frankenterm_js_addon_parity_compat.sh` → `addon_parity_compat_manifest.jsonl` |
| events / parser hooks / markers / runtime options | `scripts/frankenterm_js_advanced_api_compat.sh` → `advanced_api_compat_manifest.jsonl` |
| flow-control / link / clipboard policy under hostile input | `scripts/frankenterm_js_security_reliability_compat.sh` → `security_reliability_compat_manifest.jsonl` |
| VT conformance / xterm.js differential / WS compliance | see [`frankenterm-conformance-gates.md`](../testing/frankenterm-conformance-gates.md) |

Each cell carries `subsystem`, `scenario`, `case`, `correlation_id`, and
`passed`; failed cells are the actionable signal:

```bash
jq 'select(.passed==false)' <manifest>.jsonl
```
